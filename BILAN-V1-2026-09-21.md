## Ce qui a été livré

### Étape 1 — Fusion (19/09)
- CSS + HTML + JS regroupés dans `annotate.js`, injection automatique au chargement (balise dans `<head>` ou en fin de page).
- Configuration par attributs sur la balise `<script>` : `data-project` (clé de stockage + titre du rapport), `data-email`, `data-drawer="overlay"`, `data-multi-lines="false"`, `data-capture="false"`, `data-html2canvas="…"`.
- Variables CSS avec valeurs de repli : rendu identique sur TellUs (clair et sombre), correct sur toute autre page.
- Boutons 💬/📋 flottants créés seulement si la page n'a pas les siens (`#cmToggleBtn`/`#cmPanelBtn`).
- Vérifié sur 2 maquettes TellUs **et** une page générique (exigence du brief).

### Étape 1b — Retours de test de François (20/09)
- Repères masqués hors mode annotation ; cadre fin persistant autour de chaque élément commenté ; surlignages qui survivent au rechargement.
- Détection de zone refaite : tout élément à texte direct est ciblable ; sinon « boîte visuelle » la plus proche (fond/bordure/ombre) ; libellés lisibles avec icône par type (📍 clic, 🔲 encadré, ✏️ texte).
- Encadré ajustable (grip discret bas-droit, coins au survol), bulle déplaçable, bulle placée sans jamais recouvrir sa cible.
- Échap (annule la bulle, sinon quitte le mode) ; raccourci **Alt+A / ⌥+A** (ignoré pendant la saisie).
- Double-clic = mot, triple-clic = paragraphe, Maj+glisser = sélection précise ; bulle du clic simple après 250 ms.
- **Sélection multiple** : ⌘/Ctrl+clic ajoute/retire des éléments ; un commentaire, un cadre par élément, même numéro, lignes fines entre eux (par défaut).
- Tiroir (liste) qui **pousse la page** (marge + ajustement des éléments fixés à l'écran) ; clic sur un item = sélection en teal sur la page + édition sur place ; commentaire actif en teal (cadres, pastilles, lignes, item de liste) ; effet teal → orange à l'enregistrement.

### Étape 2 — Fiche rapport (20/09)
- **Catégorie** proposée par règles de mots-clés locales (zéro IA) : bug visuel, bug fonctionnel, ajustement visuel, texte à changer, changement de comportement, suggestion, question, à classer (défaut). Modifiable dans la bulle, badge « auto ».
- **Bloc technique** par ticket : sélecteur(s) DOM, libellés, type, citation, page (sans paramètres d'URL), position relative, fenêtre/zoom, navigateur/OS, thème, 5 dernières erreurs console (écoutées dès le chargement), date. Visible dans la liste (« détails techniques »).

### Étapes 3 + 4 — Cycle de vie, rapport, retour (20–21/09)
- Statuts : **nouveau → signalé → pris en compte → résolu**, branche **complément demandé** (réponse sans modifier l'original). ✓ manuel = résolu par moi. Tout ce qui a quitté « nouveau » est **verrouillé** ; un signalé peut être **rouvert** (renvoyé avec « remplace la version du … »).
- **Rapport** : fichier Markdown `annotate-<projet>-R-AAAA-MM-JJ-n.md` (texte lisible + bloc JSON par ticket + consigne de réponse pour la session Claude). Périmètre par défaut « nouveautés », option « complet ». Télécharger / Copier / Envoyer (mail). Générer marque les tickets signalés après confirmation.
- **Retour** : « Coller un retour » dans le tiroir — bloc texte, une ligne par ticket (`<id> pris_en_compte` / `resolu | message` / `complement | question`), historique par ticket. Même format prévu pour le retour automatique en V2.

### Étape 5 — Capture d'écran (21/09)
- Chaque encadré reçoit une capture JPEG de la zone (html2canvas chargé depuis jsDelivr uniquement au premier encadré), 800 px max, calques exclus, refaite si l'encadré est ajusté. Vignette + plein écran, image embarquée dans le rapport. Budget 3 Mo (les plus anciennes retirées).

## Principe d'architecture confirmé le 21/09

Annotate est un **produit à part entière**, avec sa propre infrastructure : son dépôt GitHub (script via jsDelivr), **son propre projet Supabase** (une base pour tous les projets, colonne `projet`), Vercel/fonctions seulement si un tableau de bord ou une fonction serveur devient nécessaire. Il n'est jamais branché sur l'infra d'un site hôte (pas sur le Supabase de TellUs-app). Il s'appliquera à tous les projets de dev de François.

## Ce que la V1 ne fait PAS (et qui bloque le live)

1. **Invisible par défaut** sur un site public : aujourd'hui les boutons 💬/📋 sont visibles de tous. Prévu V2 (raccourci secret + paramètre d'URL mémorisé).
2. **Collecte centralisée** : les commentaires restent dans le navigateur de chaque personne ; on les récupère par rapport (Copier/Télécharger/mail). Prévu V2 (Supabase, table `annotations`, policy « ajout seul », rate-limit navigateur).
3. **Hébergement du script** : pas encore sur GitHub + jsDelivr (tranché, pas fait) ; pas d'intégration dans un projet de code (TellUs-app est Next.js 14, App Router, Supabase, Vercel — `~/Dev/TellUs-app`).
4. **Retour automatique** (issues GitHub, statut visible côté utilisateur final) : V2.
5. Points ouverts du cadrage : nom définitif du produit ; mapping catégorie → niveau d'autonomie ; moment du passage manuel → automatique du pipeline.

## Ce qui a été appris (utile pour la suite)

- Le tiroir ne peut pas « rétrécir la fenêtre » (seule une extension le peut) : d'où la marge + ajustement des éléments fixes, et l'intérêt de la V2.5.
- Les captures JPEG et le stockage local : ~5 Mo par origine, d'où le budget d'images ; en V2 les images iront dans Supabase Storage.
- Un site live change de DOM plus souvent qu'une maquette : les sélecteurs `nth-of-type` restent robustes aux redimensionnements mais pas à un changement de structure — à surveiller en V2 (identifiant de page stable, cf. journal du brief).
